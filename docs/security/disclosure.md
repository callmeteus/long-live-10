# Vulnerability disclosure policy

## Reporting

To report a vulnerability, use a private channel:

- Email: security@longlive10.dev (if unavailable, open a private GitHub security advisory)
- Do not file public GitHub issues for potential vulnerabilities

Include as much detail as possible:

- Description and impact
- Affected builds/versions
- Steps to reproduce
- Proof of concept (if safe to share)
- Suggested mitigations or fixes

## Triage

- Acknowledge within 72 hours
- Assess severity and affected scope
- Determine if a fix/mitigation is possible within the project's bounds (bounded, reversible, no licensing/activation bypasses)
- If the report requires coordination with Microsoft, we will coordinate privately

## Disclosure timeline

- We aim to work with the reporter on a reasonable timeline
- We will not publicly disclose before a fix/mitigation is available or with the reporter's agreement
- If exploitation is active and a safe mitigation exists, we may document the mitigation privately first

## Safe harbor

We will not pursue legal action against researchers who make a good faith effort to follow this policy.

## Scope

This policy applies to the Long Live 10 project (agent, updater, compatibility catalog, release tooling). Host-specific issues outside the project are out of scope.

## Updates

This policy may be updated; the latest version is in this repository.
